## J
Algorithm itself isn't that difficult: taking care of 0 was the hardest part. And missing that part in the implementation cost me extra 30 minutes. 

Main observation: there's no need to visit the same location twice, so keeping track of 'when we can first reach the $i$th location - $dp[i]$' is enough. And since there are only N locations, it is guaranteed that the $max(dp[i]) \leq N$

However, there needs one refining on the definition: the reach must be through the teleport, as if you don't reach it from the teleport, it's not guaranteed you can go to $(i+1) % N$ location the next turn. 
- This only applies to $dp[0]$, so initializing $dp[0] = \inf$ not $dp[0] = 0$ is enough. 

## D
Main observation: The satisfying components can be only as large as 4 vertices. 

Count the edge numbers. LHS: number of edges needed for n vertices to be connected, times two as there are two colors. RHS: the maximum number of edges, considering that $deg(v) \leq 3,\forall v$. Given $n$ vertices, 

$2 \times (n-1) \leq \frac{3}{2} \times n \rightarrow n\leq 4$

## E

(1) For the lexigraphically smallest, suppose $i \lt j, a_i \gt a_j$ and $a_k \lt a_j, \forall i\lt k \lt j$. This means $a_j$ is behind $a_i$ in topological ordering. So, add an edge from $a_i$ to $a_j$.

(2) It's the same logic, in opposite direction, for the lexigraphically biggest array. 

(3) For computing this, use stack algorithm to store 'decreasing subsequence' for lexigraphically smallest topological ordering. For lexigraphically largest, use 'increasing subsequence'. And add an edge `st.top() -> arr[j]` 

Since $a_i$ is in front of the $a_j$, if the any graph is possible, adding an edge from $a_i$ to $a_j$ still keeps it possible. 

**However, this isn't the sufficient condition.** Even if (3)'s graph is complete, it might not result in the same lexigraphically earliest/latest topological ordering. This would have been sufficient condition if the problem was about finding graph that satisfies *one topological ordering*, however, this doesn't hold for working with *two topological orderings*. This is because the edge added in the second ordering might interfere with the first ordering and vice versa. 

Counter example: 
```cpp
4
3 4 2 1
4 2 3 1
```

Edge `2->3` is the problem for the first row. The earliest topological ordering then becomes `4 2 1 3`, not `3 4 2 1`. 

(4) Therefore, we must check if the completed graph still satisfies earliest/latest topological ordering. This can be done by topological ordering algorithm using priority queue. 

### Takeaway
To find if there is a possible solution,

1 - Find a candidate `x`, the most-possible solution. `x` must be possible if there is any possible solution. In other words, `x` holds all the necessary conditions. 

2 - Check if `x` is actually possible. In other words, check if `x` is sufficient.
